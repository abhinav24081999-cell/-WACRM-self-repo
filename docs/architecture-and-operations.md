# Architecture and operations

## Code map

WACRM is a TypeScript Next.js App Router application backed by Supabase Auth, Postgres, Storage and Realtime. Tailwind styles the interface. Translations are maintained in `messages/` for English, Spanish, Brazilian Portuguese and Korean.

| Inbox and messaging       | [Inbox components](../src/components/inbox), [WhatsApp HTTP endpoints](../src/app/api/whatsapp), [WhatsApp services](../src/lib/whatsapp), [social endpoints](../src/app/api/social). Privileged handlers need an authorized workspace or a verified provider mapping before accessing records. Test boundaries with two workspaces. Auth settings, storage privacy and applied schema also depend on the actual Supabase environment.

## Run locally

Use Node.js 22.12 or later. Install from the lockfile with `npm ci`. Create a local `.env.local` using a test Supabase URL and its anon key as `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Set server-only credentials for the features under test. The tracked tree at the reviewed revision has no `.env.local.example`. Use the guides linked from the [handbook](README.md) for feature-specific settings. Apply migrations in order to the test database and run `npm run dev`. Check [auth redirects](auth-emails.md) before testing recovery. Keep service-role credentials and integration secrets on the server.

Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. The [CI workflow](../.github/workflows/ci.yml) runs these checks with dummy build settings. The [migration workflow](../.github/workflows/migrations.yml) replays schema changes against a clean local database and verifies the result. Check migrations against representative existing test data as well when changing an existing schema or policy.

## Release and recover

1. Confirm the Git revision, Vercel project and linked Supabase project for the target environment. Check applied migrations, auth redirect URLs and provider callbacks against that target. For preview, use a separate Supabase project and test credentials, numbers and destinations. Verify isolation before testing writes.
2. Apply only the approved migrations in order, using compatible changes that leave existing data readable. Test the [relevant journeys](validation-and-branch-status.md). For Phase 1 and 2 SQL order and hosted Supabase settings, follow [access and auth emails](auth-emails.md).
3. Check schedules. [Vercel configuration](../vercel.json) declares daily conversion processing at 02:00 UTC. Verify that automation waits and flow timeouts have their own authenticated schedule where required. The route handlers live under [automations](../src/app/api/automations/cron) and [flows](../src/app/api/flows/cron).
4. For a rollback, identify the previous application deployment and confirm it can read the current schema. Stop affected provider sends or workers if needed. Treat database recovery as a separate change. Review backup or point-in-time recovery and the effect on writes since the backup before any restore. Recheck the inbox, login and integration behavior after recovery.

## Troubleshooting

| Symptom                               | First checks                                                                                                                                                                                                                                                      |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AI configuration fails to load        | Inspect the AI config request and server logs for the affected environment. Check role, connection, applied AI migrations and presence of provider configuration fields. Check encryption settings and provider access separately before attempting a live reply. |
| Password reset opens the wrong host   | Check the deployment origin and Supabase Site URL and redirect allow-list. See [auth emails](auth-emails.md).                                                                                                                                                     |
| Messages fail or go missing           | Check the selected sender, channel and reply window. Inspect registration, callback subscription and verification, request logs and delivery status. See [WhatsApp troubleshooting](whatsapp-connection-troubleshooting.md).                                      |
| Lead exists but no conversion arrives | Verify source identifiers, eligible milestone, rule mode, matching dataset and queue history. If the provider accepted the event, inspect provider diagnostics separately.                                                                                        |
| Wait, flow or campaign stalls         | Check scheduler calls, run or recipient records, and latest delivery status. Use supported resume controls after verifying which recipients or steps already completed.                                                                                           |
