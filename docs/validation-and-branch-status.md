# Validation and branch status

This is a code-based verification guide for main at `eb88c7e`. The expected results below are checks to run in an isolated preview, using two test workspaces and provider test assets. Provider behavior, deployed settings and production availability require separate verification.

| Area                          | Preview check                                                                                                                                                                                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auth and platform admin       | Sign in, reset a password and accept an invite with a provisioned test login. Check that a regular user has no platform Admin entry. Verify that the configured preview admin sees sample dashboard data and preview customer writes are blocked. |
| Team permissions              | Test owner/admin, agent and viewer against read and write actions. Confirm that users in workspace A cannot access workspace B's records or attachments.                                                                                          |
| WhatsApp and social inbox     | Connect test senders, receive and reply, then check provider delivery. Replay a duplicate test delivery and verify the conversation and unread count. Exercise an assignment, note, template, reaction and supported attachment.                  |
| Contacts, leads and pipelines | Import a test CSV, inspect tags and custom fields, create a lead and a deal, update each, and confirm history and workflow views. Check the contact drawer and Meta feedback badges where a linked event exists.                                  |
| Templates and broadcasts      | Sync a test template, map variables and send to a small test audience. Verify recipient state, failed sends and interrupted-broadcast resume.                                                                                                     |
| Automations and Flows         | Run inbound, keyword and scheduled examples. Verify waiting, branching, replies resuming the correct run, timeout, tag change, handoff and logs.                                                                                                  |
| AI                            | Save a test provider, try a draft and Playground, then test auto-reply, handoff and qualification. Verify that manual takeover prevents conflicting automatic replies.                                                                            |
| Lead intake and feedback      | Test Meta form capture and referrals, Google callback acknowledgement, and authenticated website intake. Check attribution, deduplication and qualification history. Queue test feedback and distinguish API receipt from provider matching.      |
| Reporting and notifications   | Compare dashboard totals and Ads Performance exports against known samples. Check date and source filters, notification seen state, browser permissions and presence.                                                                             |
| API, webhooks and MCP         | Verify scoped and revoked keys, synthetic outbound webhook delivery and signature validation, opt-in MCP writes, and test messaging through allowed scopes.                                                                                       |
